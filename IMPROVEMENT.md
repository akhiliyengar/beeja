# beeja improvement loop

How the builder improves itself. Deterministic, periodic, gated.

## Why nothing improves yet

The builder ships in `phase = calibration` with a 3-axis success vector:

```
(draft_acceptance_rate, avg_revision_passes, artifact_30d_survival_rate)
```

For that vector to drive prompt mutations, three peer artifacts must exist.
They don't, until you build them — using the builder, on itself.

## The three peer artifacts

| Artifact | Template | Job |
|---|---|---|
| **builder signal collector** | `sensor[subtype=signal_collector]` | Watch every builder invocation. Append to `~/agents/shadow/_signals/builder.jsonl`. Emit `signals.builder.*`. |
| **builder scorer** | `scorer[subtype=learned_scorer]` | Consume those signals. Fit a preference model. Emit `evals.scores.builder` as a 3-dim vector per session. |
| **builder improver** | `meta` | Read the scores, propose prompt mutations, replay-and-gate. Targets `beeja/prompts/{interview,draft,revise}.v*.md`. Has `[success.properties].monotonicity = true`. |

Bootstrap them:

```bash
beeja "signal collector for the builder; reads ~/agents/shadow/_signals/builder.jsonl"
beeja "scorer for the builder; emits a 3-dim vector per session from the signal stream"
beeja "meta-improver targeting beeja's interview/draft/revise prompts; monotonic Pareto promotions only"
```

## Triggers (whichever fires first)

| Trigger | Condition | Cadence |
|---|---|---|
| **Volume** | ≥50 new signal records since last pass | Continuous check |
| **Schedule** | Weekly cron | Even with low traffic |
| **Regression** | Any success dimension drops ≥10% in 7 days | Immediate, mid-week |

## The 9-step pipeline

The improver runs deterministically. No step is "use your judgment".

1. **Read signals.** Tail `~/agents/shadow/_signals/builder.jsonl` since
   `last_pass_ts`.
2. **Score.** Pass each session through the scorer. Get one 3-vector per session.
3. **Aggregate.** Compute current means and per-dimension trends.
4. **Identify weakest dimension.** The one with the lowest z-score vs. its
   30-day baseline.
5. **Propose 3 candidates.** GEPA / NSGA-II style mutations of the prompt
   targeting the weakest dimension. Generated by an LLM call constrained to
   "minimal diff that plausibly moves dimension X".
6. **Replay.** Run the last N sessions (default 30) through each candidate.
   Cached LLM responses make this near-free.
7. **Re-score.** Pass replays through the scorer. Get a 3-vector per
   (candidate, session).
8. **Pareto-gate.** A candidate is admissible iff its mean vector is
   *no worse on any dimension* and *strictly better on at least one*.
9. **Promote or quarantine.** The single dominating candidate (if any) is
   promoted to `prompts/<name>.v{n+1}.md`. All others go to
   `~/agents/shadow/_quarantine/<ts>/` with a one-paragraph rationale.

If no candidate dominates, the pass logs `no_promotion` and exits clean.
That is the expected outcome most of the time. Improvement is rare and
must be earned.

## What `monotonicity = true` enforces

It is the structural guard that makes the loop safe to run unattended.

- **Without it:** the improver chases the weakest dimension and silently
  trades away a stronger one. Local optima everywhere.
- **With it:** every promoted prompt is Pareto-≥ the previous prompt across
  all three dimensions. The system can only move along the Pareto frontier,
  never inward.

This is *the* property that distinguishes "self-improving" from "self-mutating".

## Cold-start fallbacks

Until volume hits 50:

- `beeja --improve --propose-only` — read whatever exists, propose candidates,
  do not promote. Useful for sanity-checking the loop end-to-end.
- **Reflection-only mode** — if N < 10, the improver skips the scorer and
  asks the LLM to critique sessions you marked as low-quality.
- **Transfer-learn** — once any *other* artifact has gone through a
  promotion, the improver can apply analogous mutation patterns to the
  builder's prompts.

## Bootstrap timeline

```
Today:       Build the three peer artifacts (above).
             Install the post-session hook.
             Run `beeja --improve --propose-only` to validate the pipeline.

Week 1-3:    Use beeja normally for your other work.
             Signals accumulate. Scorer fits its preference model.

Week 4+:     First volume-triggered pass fires (50 records hit).
             Candidates proposed → replayed → Pareto-gated.
             Either v3 promotes, or all three quarantine with rationale.

Steady-state: Weekly cadence. The builder builds itself.
```

## What "self-improvement" actually means here

It is not a property of any single component. It is a closed loop with
monotonic guards:

```
signals → score → propose → replay → gate → promote
   ↑                                            │
   └────────── new sessions use new prompt ─────┘
```

Every artifact you build with the builder generates the training data the
builder needs to improve. The loop runs whether you remember to maintain it
or not. Improvement is deterministic, periodic, and gated — never magic,
never continuous, never immediate.
